📋 MODELO 1: PREVISÃO DE STATUS FINAL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

O QUE FAZ?
  Prevê se processo será Aprovado ou Indeferido
  Input: Dados do processo até análise técnica
  Output: % de aprovação (0-100%)

DADOS NECESSÁRIOS (do banco):
  ✓ dias_para_deferimento
  ✓ valor_estimado
  ✓ num_movimentacoes
  ✓ num_anexos
  ✓ passou_analise_tecnica
  ✓ tipo_irregularidade
  ✓ estado, concessionaria

ARQUIVOS A CRIAR:
  1. backend/ia/train_status_model.py      (Treinar modelo)
  2. backend/handlers/ml_prediction.go     (Integração Go)
  3. Adicionar rota em backend/routes/routes.go

COMANDO:
  python backend/ia/train_status_model.py
  (gera: backend/ia/models/status_model.pkl)

ENDPOINT:
  GET /api/v1/processo/:id/predict-status
  RESPONSE: {
    "prediction": "APROVADO",
    "approval_probability_percent": 78.5,
    "confidence": 85.2,
    "recommendation": "✅ Processo deve ser APROVADO"
  }

  POST /api/v1/detect/anomaly
  RESPONSE: {
    "is_anomaly": true,
    "anomaly_score": 0.87,
    "risk_level": "Alto"
  }

💡 DICAS IMPORTANTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. DADOS LIMPEZA
   ✓ Remover NaNs antes de treinar
   ✓ Normalizar valores (StandardScaler)
   ✓ Codificar categóricas (LabelEncoder ou OneHot)

2. MODELOS ESCOLHIDOS
   ✓ Status: GradientBoostingClassifier (melhor para classificação)
   ✓ Anomalia: IsolationForest (detecção sem label)
   ✓ SLA: RandomForestRegressor (regressão)

3. VALIDAÇÃO
   ✓ Sempre usar train/test split (80/20)
   ✓ Cross-validation para maior confiança
   ✓ Monitorar accuracy/precision/recall

4. DEPLOYMENT
   ✓ Trenar localmente, salvar .pkl
   ✓ API Python serve em porta 8001
   ✓ Backend Go chama HTTP para API
   ✓ Fácil atualizar sem reiniciar backend
